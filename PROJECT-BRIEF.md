# The Oasis — project brief

Updated 2026-10-26. F1 is verified. The owner authorized a separate [LV1 private LAN visitor pilot](docs/planning/LAN-PILOT.md), now implemented with its own remaining acceptance gates. S1/S2 remain planned. “RPO HUB” is the former working/repository name; historical decisions and evidence remain in the [decision log](docs/planning/DECISIONS.md) and [legacy crosswalk](docs/provenance/LEGACY-CROSSWALK.md).

| Field | Current position |
| --- | --- |
| Product name | **The Oasis**, selected by the owner |
| Repository | `killacalione/The-Oasis`, public Apache-2.0 project; existing repository renamed in place |
| Public project site | `https://killacalione.github.io/The-Oasis/`; publication state is verified separately in [work state](docs/planning/WORK-STATE.md) |
| Product | A persistent community hub where people meet through a central Hub, visit community-made worlds, personalize player-owned avatars and personal Homes, and create worlds themselves |
| First arrival | Create account → create/select avatar → first successful spawn in the Hub, with the launch dashboard available; these are planned product behaviors, not live services |
| Returning arrival | Resume last confirmed world/version, coordinate frame, exact X/Y/Z, facing and save revision by default; after first arrival, choose Resume, Always Hub or Always Home |
| Current phase | LV1 private LAN visitor pilot: implemented, physical/extended-operation acceptance pending; F1 verified; S1/S2 planned |
| Application state | A built-in 3D Hub/island/observatory visitor loop with five-client authority, colors and confirmed saves exists. No real account, Home, guest runtime, voice, publishing or public application service. |
| S1 proof | Small internal local prototype: Hub/dashboard, locally owned avatar appearance and Home, shared authoring contract, two original worlds, personalization, portals, exact-location recovery and portable local save/export |
| Long-term audience | Children, teens and adults worldwide, subject to actual regional, age/guardian, privacy, accessibility, operating and financial readiness |
| Public-release requirements | Eligible public world discovery, text/proximity/party voice, trusted direct publishing and owner-selected visibility, subject to reviewed policy and server enforcement |
| Stack | Foundation tooling stays dependency-free/static. LV1 pins Node24, TypeScript, Babylon, modular Colyseus and SQLite. Production/creator/media/provider decisions remain separate. |
| Funding/operations | Low-cost preference; sustainable public operating budget, named operator and response staffing are unverified. |
| Governance | Owner-led maintenance with reviewed community proposals and contributions. |
